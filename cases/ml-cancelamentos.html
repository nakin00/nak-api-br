Cancelamento pago no ML chega no Slack em 5 min

apps-script mercado-livre oauth slack

Apps Script consulta a API do ML a cada 5 minutos, filtra cancelamentos de pedidos que já estavam pagos, e avisa no Slack. Evita que a mercadoria saia depois do cancelamento.

14:00:00 trigger 5min disparado
14:00:01 ML conta-1: 0 cancelados
14:00:02 ML conta-2: 1 cancelado
14:00:02 pedido 2000123: status=approved
14:00:03 slack: "Cancelado pago — pedido 2000123"
14:00:03 dedup salvo (500 IDs em cache)
01 · Dor operacional

Mercadoria sai antes da equipe ver o cancelamento

O pedido cai pago no Mercado Livre. Separação rola, motoboy pega, mercadoria sai. No meio do caminho — às vezes minutos depois do pagamento — o cliente cancela.

Se ninguém da equipe vê o cancelamento rápido, o pacote já está com o transportador. Quando a devolução chega de volta: frete pago duas vezes, estoque pra repor, dinheiro pra estornar.

"O pior cenário é descobrir o cancelamento na conciliação do mês. Quando vê, o prejuízo já aconteceu três vezes."

02 · Impacto do problema

Custo invisível somando todo mês

  • Frete duplo — ida pro cliente, volta pra base.
  • Reposição de estoque fora de ordem — produto volta sem aviso, vai pra prateleira fora da rotina.
  • Estorno só descoberto na conciliação — dinheiro saiu antes da equipe entender o que aconteceu.
  • Equipe atendendo cliente no escuro — cliente liga perguntando do estorno, equipe não sabe que cancelou.
  • Painel do ML sem aviso ativo — precisa abrir e procurar pra saber.
03 · Solução criada

Polling 5 min na API do ML + filtro de pagamento + dedup

Um Apps Script roda a cada 5 minutos. Pra cada conta do ML, faz uma chamada simples na API: dá os pedidos cancelados nas últimas 24h.

Filtra os que estavam realmente pagos (status approved, refunded, in_process, in_mediation, charged_back) — descarta os que cancelaram antes do pagamento, que não importam.

  • Trigger 5 min — janela suficiente pra pegar antes da mercadoria sair, sem estourar limite da API.
  • Filtro de status de pagamento — só interessa cancelamento que CUSTOU. Cancelamento sem pagamento é ruído.
  • Dedup via PropertiesService — chave NOTIFIED_CANCEL_<conta>, mantém os 500 IDs mais recentes. Não notifica o mesmo pedido duas vezes.
  • OAuth ML via Web App — Apps Script publicado como Web App pra ter URL de redirect. Múltiplas redirect URIs convivem com o projeto ml_etiquetas sem conflito.
  • Webhook Slack por conta — canal recebe a notificação com link direto pro pedido.

06 · Insights aprendidos

O que essa automação ensinou

"5 minutos de latência em alerta é a diferença entre 'voltei do correio' e 'cliente pediu pra cancelar antes'."

"OAuth do ML obriga publicar Apps Script como Web App. Não tem jeito mais bonito. Achei chato, fiz, segui."

"Deduplicar via PropertiesService funcionou. Tentei via Sheets primeiro — era lento demais pra polling de 5 minutos."

O ganho aqui não é "tecnologia avançada". É frequência e filtro certo. Olhar mais vezes e ignorar o que não importa.
